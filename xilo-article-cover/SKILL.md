# Xilo Article Cover

先确认用户选择的风格，把文章中的真实主题和读者价值压缩成封面标题，再用固定 IP 生成跨平台封面。风格选择、标题确认、视觉确认和最终交付是独立阶段。

## 开始前

1. 默认先请用户从第 2 节的八种风格中单选或多选。用户已明确给出风格名称，或回应本次风格列表的序号时，直接采用，不重复询问。标题、构图想法、Logo 和品牌色都不等于已选风格；未选风格时不能生成图片。若正文等关键输入也缺失，可在同一次提问中索要。
2. 读取用户给出的文章路径、Markdown、Obsidian 笔记或粘贴正文。只有选题没有正文时，除非用户明确要概念封面，否则先索要文章。
3. 确认输出类型：
   - `公众号文章封面`
   - `X Articles 文章封面`
   - `视频封面`
   用户已明确时不要重复询问。输出类型必须先于标题确认，因为画幅决定标题长度和断行。
4. 读取 [references/title-design.md](references/title-design.md) 和 [references/platform-formats.md](references/platform-formats.md)。确认风格后读取 [references/styles.md](references/styles.md)。
5. 读取 [references/character.md](references/character.md)。默认使用其中的示例小水獭；用户提供自己的角色描述或参考图时，完整替换角色身份设定，不混用。用户提供参考图时必须打开并传给图片工具，只锁定身份，不复制姿势或背景。
6. 本包用文字定义八种风格，不附带作者的角色图或封面示例图。用户提供风格参考时，先打开再传入，只借鉴媒介、色系、视觉密度和必要结构，不复制旧标题、旧主题或人物。
7. 用户只要封面提示词时，交付完整可复制提示词，不调用图片生成工具。风格、标题与画幅齐备后，按 [references/prompt-template.md](references/prompt-template.md) 填写；缺少正文证据时不编造结果。

## 1. 提炼封面 Brief

从文章中记录：

`主题 / 目标读者 / 可验证结果 / 读者获得感 / 核心工具或对象 / 痛点 / 方法类型 / 可视化证据 / 不可夸大边界`

- 数字、版本、收益、结果和产品能力必须能在文章中定位。没有事实支撑时走“获得感 + 认知反转”，不编数字。
- 证据优先使用文章已有截图、产品界面、真实对象或明确流程；没有真实证据时做概念化视觉，不伪装成真实 UI 或实测截图。
- 一个主证据、最多两个辅助信号。不要把全文流程塞进封面。
- 标题必须先通过“三秒可读性”检查：脱离正文后，读者仍能看懂具体讲什么、能得到什么，以及为什么值得点开。流程步骤、前置准备和操作成本不能替代获得感。

## 2. 确认风格与数量

让用户单选或多选：

1. `纯白高透视破框`
2. `蜡笔主题剪贴`
3. `电商素材检查`
4. `纯白马赛克聚焦`
5. `深绿手绘`
6. `绿色对话框漫画`
7. `绿色复古掌机`
8. `绿色剪纸杂志`

每个所选风格只生成一套，不自动生成同风格多变体。标题与画幅确认后，生成前列出：`输出类型 / 标题与断行 / 小标签 / 所选风格 / 目标画幅 / 最终文件数 / 预览文件数`。

### 构图策划

风格确定后，在写生成提示词前内部比较可行构图，再确定：`镜头与景别 / 主动线与视觉终点 / IP 与主题对象的动作关系 / 标题分区`。按主题和标题长度选择，不额外要求用户先选构图，也不为比较方案自动多生图片。

- 风格识别来自媒介、配色和必要结构特征，例如掌机的屏幕与控制键、聚焦样式的单一清晰框；不把参考图的位置关系当成风格本身。
- 有当前对话已见封面或已保存提示词时，先对比最近同风格方案；没有时对比用户提供的风格参考；没有参考图时按文字风格骨架策划。新主题或用户反馈“总是这个布局”时，在上述四项中至少改变两项。换色、镜像、只挪 Logo 或换商品不能算重新构图；动线按叙事选择，不机械左右轮换。
- 用户明确要求沿用版式、只改文字或 Logo 时，保持未提及部分；不得为了求变化重排已确认构图。
- 提示词分开说明角色参考、风格参考和当次构图的职责。标题可置顶、置底或侧置，仍须水平、清楚、不遮挡关键动作。可选构图不固定为“上方大标题＋中间 IP＋右下成果卡”，掌机不默认使用横向跑酷关卡。

## 3. 提供 5 套封面标题

用户尚未给出精确标题时，按 [references/title-design.md](references/title-design.md) 的价值与清晰度门禁内部生成更多候选，再筛成 5 套不同路线。每套必须交付：

1. `主标题`：逐字文本；
2. `断行`：明确第一行、第二行；
3. `小标签`：没有必要就写“无”；
4. `结果 / 获得感`：分别说明由哪部分承担；
5. `适用说明`：说明更适合哪种画幅或风格；
6. `短版备用`：只有原标题在小画幅明显过长时才提供。

给出推荐 1 套及理由，然后停下等待用户确认。未经确认不得生成封面。用户提供精确标题时视为已选文案，保留原文、大小写、标点和标签，不自行改写；仍须单独确认风格。

## 4. 按平台生成

用户要求生成图片时，使用当前环境可用的图片生成工具（例如 `image_gen`）；无可用工具时只交付提示词并说明限制。每一张最终图都是独立、原生画幅的完整构图，不把其他比例机械裁切、补边、模糊扩图或画布扩展成目标比例。对全部八种风格，把 `references/styles.md` 对应风格的媒介、配色和必要结构写入提示词。角色身份、风格和当次构图分开声明；有用户提供的参考图时同时传入，没有时按文字设定执行，不宣称已使用图像参考。

### 公众号文章封面

每个风格生成两张最终图：

- 原生 `2.35:1` 主封面；
- 原生 `1:1` 辅封面。

辅封面必须独立构图，只保留一个 IP 动作或 2–4 个字的核心短语；不得把完整主标题缩小塞入方图。两张生成并保存后，运行 `scripts/build_wechat_preview.py` 生成“左主封面、右辅封面”的组合预览。组合预览不是上传用最终图。

公众号封面完成后，询问用户是否还要为同一文章生成 `X Articles 5:2` 封面；不要询问主页横幅或普通帖子配图。

### X Articles 文章封面

每个风格生成一张原生 `5:2` 文章头图。`5:2` 是本工作流约定的规格，不写成 X 官方公布比例。复用已确认标题、IP、主题证据和风格，但为 5:2 独立排版。

### 视频封面

每个风格先生成一张原生 `3:4` 竖版视频封面。完成并交付后，询问用户是否同步生成横版；确认后为每个已选风格分别生成：

- 原生 `16:9`；
- 原生 `4:3`。

不生成 YouTube Shorts `9:16` 分支。跨画幅锁定标题、IP 身份、主证据、风格媒介、情绪和配色，只重新设计空间关系。

## 5. 全局视觉合同

- 固定 IP：默认按 `references/character.md` 的小水獭设定；用户已提供角色时以其设定为准。
- IP 气质偏呆萌。允许震惊、顿悟、兴奋、慌张和夸张动作，但不得横眉冷对、凶狠、攻击性或成人化。
- 所有可读文字横平竖直、基线平直；禁止旋转、倾斜、斜体、弧形排字和透视扭曲。画面动势由角色、对象、速度线和空间透视完成，不靠歪字。
- 默认主题色为 `#28A85B`。大面积绿色使用舒适的深浅层次，避免荧光绿、灰橄榄绿、脏米白和发灰白底。
- 用户提供品牌 Logo 时，保留原有字形、图形和颜色，让它成为角色正在展示或操作的主题对象，并与场景产生明确接触关系；除非用户明确要求角标，否则不要把 Logo 孤立放在画面角落或标题上方。图像模型重绘无法保证像素级一致，交付时如实说明。
- 标题由图像模型与画面一次性生成。用户反馈逐字错误后重生或定向编辑，不用 HTML、SVG、PIL、Canvas 或本地字体把标题贴上去。
- 除确认的小标签外，不生成随机英文、伪 Logo、水印、路径、字幕或无法核实的小字。
- 人体结构自然；动作优先清楚、可读、有接触关系，拒绝多肢、坏手、断肢、身体与物件融合。

## 6. 生成后交付与修改

每张图生成一次后直接呈现，由用户决定是否修改。不主动做视觉审查或重复生成，也不把“已生成”表述为“用户已认可”。仅核对文件存在、格式与尺寸；比例可用 `scripts/validate_cover.py` 检查，脚本依赖 Python 3 和 Pillow。比例不符时如实报告，不自动裁切、补边或重画。

用户指出问题后，只改被点名的画幅，锁定已确认的标题、角色、主证据和风格。按反馈核对文字、角色、动作、Logo、主题证据及风格合同。新版本另存，不覆盖原文件。工具没有返回文件或文件损坏时先说明技术错误，再按工具的重试规则处理。

## 7. 输出与命名

- 优先保存到用户指定目录；否则使用当前项目的 `generated-covers/<YYYY-MM-DD>-<文章标题>/`。日期按用户时区。先按文章标题主体查找并复用已有目录，不写死个人知识库路径。
- 不要只留下图像工具的临时预览。
- 推荐名称：`<主题-slug>-<platform>-<style>-<ratio>.png`。
- 公众号组合预览加后缀 `-pair-preview.png`。
- 交付时报告每张最终图的绝对路径、像素尺寸、平台、风格和技术检查结果；预览图单独标记。

## 边界

- 不负责文章正文写作、正文配图、视频剪辑、上传或发布。
- 生成前确认风格、文案与画幅；生成后由用户决定视觉效果是否接受。
- X Articles 的 `5:2` 是本 Skill 的工作流约定，不宣称为平台官方规格。用户要求核对平台规范时另行实时查询。
