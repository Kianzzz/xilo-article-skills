# Xilo Article Peitu

## 目标

先用一张日期与一句话构成的横版 IP 浮动 GIF 为文章开场，再把文章中的认知锚点转译成一组风格统一、分布合理、可以直接插入正文的 16:9 纸感手绘插图。成图应让读者先感到有趣和略微荒诞，再快速看懂当前段落的结构。

本 Skill 不内置任何 IP。所有角色外形、参考图、刊头文字和印章都来自用户的 **IP 档案**。

## 第 0 步：加载或初始化 IP 档案

IP 档案目录（以下记为 `<ip-dir>`）：环境变量 `XILO_ARTICLE_PEITU_IP_DIR` 指定的目录；未设置时为 `~/.config/xilo-article-peitu/`。档案保存在 Skill 目录之外，更新或重装 Skill 不会丢失。

每次执行先检查 `<ip-dir>/ip-profile.md`：

- **存在**：读取档案，打开其中列出的全部参考图，后续所有 `{IP …}` 占位都从档案取值。档案里的描述与参考图冲突时以参考图为准，并提示用户更新档案。
- **不存在（首次运行）**：停止配图流程，按 `references/ip-setup.md` 引导用户登记 IP。没有完成登记前，不生成任何图片，也不得自行编造或沿用示例角色。用户明确表示“这次不要 IP，只要纯装置图”时，可以零角色执行本次任务，但仍不写入档案。

用户要求“换 IP”“改角色”“加一个角色”时，同样走 `references/ip-setup.md` 的更新分支，先备份旧档案。

## 资源路由

执行任务前读取：

- `<ip-dir>/ip-profile.md` 及其中列出的参考图：角色身份、比例、配色、眼睛与动作职责。
- `references/style-dna.md`：画风、配色层级和构图基线（色板以档案为准，未设置时用默认绿系）。
- `references/qa-checklist.md`：画面规格清单，用于写提示词和按反馈修改。

按分支读取：

- 日期首图读取 `references/date-header.md`；首图按头部目标尺寸调用 `scripts/compose_date_header.py` 合成，不套用正文装置构图模板。档案提供了首图尺寸参考图时一并打开。
- 设计隐喻与构图时读取 `references/composition-patterns.md`。
- 生成正文或目录图片时读取 `references/prompt-template.md`。

参考图只提供角色造型、笔触、比例与配色基线；当前文章决定物件、布局和叙事。档案提供笔触参考图时，生成前同时传入，只锁定线条密度与粗细变化，不复制其姿势或背景。

## 工作流

### 1. 确定首图分支

为整篇文章规划或生成配图时，默认增加 1 张 3:1（2400×800）日期首图 GIF，单独计数；档案登记了印章时叠加印章。用户明确不要首图、只处理指定段落或只修某张图时，不扩大任务范围。已有首图时复用或按要求更新，不重复插入。只要求首图时仅执行首图分支。只修改本 Skill 时不自动替任何文章生图或改稿。

读取全文后按 `references/date-header.md` 记录当日日期、时区、一句话文案、文章处境及场景依据、IP 动作姿势、主道具与接触关系、实例数和动效参数。没有正文时不得编造文章总结；用户已提供主题时，可据主题拟一句原创文案和场景，明确标为主题创作。正文、主题、文案均缺失时才询问。

### 2. 解析正文与权重

读取完整正文，按二级章节记录：

- 字符量和信息密度
- 核心判断、转折、步骤与闭环
- 适合视觉化的认知锚点
- 连续纯文字区段长度

核心教程章节达到全文约 40%，或内部包含 4 个以上步骤或转折时，在章节内部安排 3–5 张图。较短章节按表达需要安排 0–2 张。章节总览与内部步骤图各自承担独立功能，分别计数。

正文超过 2000 个字符时，默认在第一个二级标题前增加 1 张目录图；已有目录视觉或用户指定其他方案时沿用现状。

正文配图（含目录图，不含首图）默认安排 4–8 张图；短文安排 1–3 张；包含长教程章节的文章可扩展到 9 张。最终数量由认知锚点和章节权重决定。

### 3. 建立文章级视觉规格

同一篇文章先固定一份视觉规格。所有图共用背景、笔触、配色与 IP 身份比例；以下装置尺度、人物画布占比、主体位置和短词数量只适用于正文与目录图，首图使用 `references/date-header.md` 的构图规格：

```text
画幅：16:9
背景：干净纯白 #FFFFFF，不带米色、奶油色或可见纸纹
风格：深褐断线手绘 + 档案色板的浅中深分层（默认绿系，见 style-dna.md）
锚点色 / 装置主色 / 辅助浅色 / 结构深色 / 近白：取自档案色板
人物角色：档案中的头身比（默认 2.70，允许 ±0.05），头顶/头部饰物不计入
人物/伙伴高度比：取自档案（默认 1.8–2.2）
人物/画布高度护栏：常规图 24%–32%，目录图或横向低装置图 22%–32%；任何人物不得超过 35%
装置尺度模式：高装置 / 低矮横向装置（二选一）
高装置模式：核心装置高度占画布 70%–78%，且至少为人物高度的 2.2 倍
低矮横向模式：核心装置宽度至少为单个人物高度的 5 倍，并占画布宽度 75%–85%
主判据——超大物件锚点：核心功能模块或容器高度达到完整人物的 1.4–2.2 倍；次级卡片、把手或控制件达到人物头部的 0.8–1.5 倍
普通主体群宽度：画布的 65%–78%；水平中心：45%–55%
中文标注：3–5 个短词
装置复杂度：中等
```

档案只有伙伴型角色（没有人物）时，把“人物”指标换成档案中最高角色的高度，并在 shot list 注明。

方向性结构可以使用非对称构图，例如前后对比、输入输出和回流。此时留白必须承担流向、对比或反馈功能，并在 shot list 中说明。

### 4. 输出 shot list

用户只要求分析时，交付 shot list；用户明确要求生成时，完成 shot list 后直接进入生图。

首图使用 `references/date-header.md` 的首图规格卡；每张正文图记录：

- 插入位置与阅读角色：认知锚点之前 / 结果证据之后
- 主题与核心意思
- 结构类型与原创物理隐喻
- 主体轮廓、主体宽度与视觉中心
- 装置尺度模式、人物占画布高度目标和超大物件锚点
- 留白用途
- 每个出场角色的具体动作（按档案中的动作职责分配）
- 每个角色的目标实例数
- 3–5 个中文标注
- 当前图片的构图风险

最后附覆盖审计：列出各二级章节的配图数、核心章节内部覆盖情况和最长连续纯文字区段。

### 5. 处理目录图

目录图提炼正文真实存在的 3–5 个一级阅读部分，按从左到右的顺序呈现。使用低矮、连续、可顺序阅读的主体轮廓：

- 核心装置宽高比至少约 2:1，主体群宽度约占画布 75%–85%，视觉中心位于画面中部。
- 人物高度约占画布 22%–32%，不得为了填满上方留白而放大；装置总宽至少为单个人物高度的 5 倍，每个阶段的主要模块高度至少为人物的 1.4 倍。
- 优先采用横向工作台、分拣台、长桌、书签带、轨道或横向抽屉。
- 各角色分别承担展开、递送、推动和引导阅读顺序的动作。

生成时调用 `references/prompt-template.md` 中的目录图模板。

### 6. 单张生成

首图按 `references/date-header.md` 生成静态层并合成为真实 GIF。正文每张图单独调用当前环境可用的图片生成工具。提示词由三块组成，顺序固定：

1. 固定视觉 DNA：画风、配色，以及从档案拼出的角色外形与比例。
2. 当前图片内容：核心意思、物理隐喻、角色动作、中文标注。
3. 当前图片构图：主体轮廓、宽度、视觉中心、留白用途。

构图硬规格放在提示词末尾，控制在 5–7 条。

正文默认实例数取档案的“正文默认出场”。提示词必须逐项写出 shot list 的目标实例数；目标为 1 时写 `exactly one`，并明确禁止该角色重复、身份标志重复（如第二个头饰）。目标为 0 的角色在计数块中明确禁止；不得一边要求 `exactly one`，一边要求省略同一角色。

档案为角色规定了默认眼睛状态时，只有 shot list 在生成前因语义需要记录了例外，才改变。

### 7. 定位生成文件

图片源文件优先级：

1. 当前生成结果返回的保存路径。
2. 生成工具的默认输出目录中本次调用新增的图片（例如 Codex 的 `${CODEX_HOME:-$HOME/.codex}/generated_images/`）。
3. 会话记录中的 PNG base64 结果，可用 `scripts/extract_imagegen_results.py <session.jsonl> <输出目录>` 恢复。

每次调用前创建时间标记，并据此定位新增文件。生成结果缺少本地文件与可恢复数据时，交付 shot list、提示词和当前阻塞说明。

### 8. 一次生成，直接交付

每张图只生成一次，生成后直接保存到配图目录并插入文章，不设“全部审校通过才能交付”的门槛，也不因为发现问题而自动重新生成或局部编辑。是否返工由用户看图后决定。

只有技术性失败才允许重试，且不算质量返工：生成工具没有返回文件、文件损坏、首图场景层没有可用透明背景（按 `references/date-header.md` 做洋红底编辑）、GIF 合成脚本报错。

生成后用图片查看工具打开每张原图看一遍，把一眼可见的问题写进交付说明，例如：角色数量或身份标志不对、人物明显比装置还抢眼、档案规定的眼睛或饰物画错、中文标注写错、首图日号被挡到认不出。只记录、不返工；不必为交付逐项填写审校卡或做像素测量。

### 9. 按用户反馈修改

用户指出问题后，只改被点名的图，优先局部编辑，必要时才整张重画；修改后同样直接替换文件并交付，不追加额外轮次。`references/qa-checklist.md` 是写提示词时的规格和修改时的依据，不是交付门槛。

返工路由：

- 语义偏差：重新设计物理隐喻。
- 风格漂移：保留主题，强化固定视觉 DNA 后重画。
- 构图偏差：保留隐喻，重写主体宽度、中心和留白规格。
- 局部文字问题：局部编辑；多处文字问题则减少标注后重画。
- 角色数量错误：保留装置与布局，删除重复实例。
- 人物间尺度不一致：以较符合参考图的一方为基准统一大小。
- 人物相对场景过大：先按当前尺度模式重写人物占画布高度，再放大核心装置。
- 身份规则错误（如眼睛、饰物）：按档案逐项同时修复，不能只改一处。

### 10. 保存与插入

图片目录优先级：

1. 用户指定的目录。
2. 档案中登记的“默认配图目录”（可含 `<日期>` 与 `<文章标题>` 占位）。
3. Obsidian 知识库内：库的附件目录（按 `.obsidian/app.json` 的 `attachmentFolderPath`）下的 `配图/<日期>-<文章标题>/`。
4. 其他项目：当前项目的 `generated-images/`。

先查找包含文章标题主体的已有目录并复用。

首图使用 `<article-topic>-peitu-00-date-header.gif`，同时保留同名 `.png` 静态首帧。正文从 `01` 开始，不因增加首图重编号已有正文图。正式文章默认只引用 GIF；目标平台无法播放时明确说明并采用 PNG。

正文文件名：`<article-topic>-peitu-<sequence>-<image-topic>.png`

- `article-topic`：从文章标题提炼 2–4 个小写拼音词、英文词或稳定缩写，例如 `codex-tushu`。
- `sequence`：两位数字序号；`image-topic`：英文短主题。
- 版本迭代在末尾增加 `-v2`、`-v3`。

Obsidian 文章使用 Wikilink：文件名在库中唯一时用最短链接 `![[xxx.png]]`，重名时用从库根开始的完整路径。非 Obsidian 文章使用标准 Markdown 相对路径。

插入位置遵循阅读角色：

- 首图放在 frontmatter 和已有 H1 之后、导语及首段正文之前；无 H1 时放在 frontmatter 之后。不得插入 YAML 内或改写标题、正文。
- 目录图放在第一个主要章节之前，位于首图之后。
- 概念图、步骤图和结构图放在对应标题之后、正文展开之前。
- 截图、案例结果和证据图放在产生该结果的说明之后。

只编辑图片引用和必要空行。完成后检查：引用数量、文件存在、短链接唯一、文件命名、插入位置和尺寸格式。

## 交付

说明首图 GIF 与正文图各自数量、首图日期/时区/一句话、各图用途、保存目录、插入位置，以及看图时发现的问题（只列出，等用户决定是否修改）。
